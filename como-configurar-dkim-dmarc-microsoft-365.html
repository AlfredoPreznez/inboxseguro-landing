Cómo configurar DKIM y DMARC en Microsoft 365

Guía basada en la documentación oficial de Microsoft 365. Verifica cada cambio con las herramientas de diagnóstico gratuitas de InboxSeguro.

Antes de empezar

Necesitas acceso de administrador al DNS del dominio (p. ej. ejemplo.cl) y a la consola de Microsoft 365. Lee también qué es DMARC y cómo activarlo y los términos política DMARC y selector DKIM.

El portal Microsoft Defender / Exchange admin center cambia de nombre y menús; sigue la URL canónica de Microsoft Learn si la consola no coincide con capturas antiguas.

Pasos numerados

  1. 1. Orden recomendado: SPF, luego DKIM, luego DMARC

    Microsoft recomienda autenticación SPF → DKIM → DMARC para cada dominio personalizado que envíe correo. SPF es la lista de orígenes autorizados en DNS; sigue la guía SPF de Microsoft Learn para tu dominio en ejemplo.cl.

  2. 2. Obtén los dos CNAME DKIM (antes del interruptor)

    En el Microsoft Defender portal, Email authentication settings → DKIM, abre el dominio personalizado. Microsoft muestra (o puedes obtener con Get-DkimSigningConfig) dos hosts selector1._domainkey y selector2._domainkey que apuntan al formato vigente, por ejemplo selector1-ejemplo-cl._domainkey..-v1.dkim.mail.microsoft. El formato antiguo (hacia *.onmicrosoft.com) y el nuevo no pueden coexistir para el mismo selector: usa solo los valores que Microsoft te muestra ahora.

  3. 3. Publica los CNAME en el DNS

    En el DNS de ejemplo.cl crea exactamente esos dos CNAME. Espera unos minutos (o más) a que Microsoft 365 los detecte.

  4. 4. Activa la firma DKIM (interruptor Enabled)

    Cuando los CNAME estén publicados, desliza el interruptor Sign messages for this domain with DKIM signatures a Enabled (o Set-DkimSigningConfig -Enabled $true). Si los CNAME faltan, el portal muestra error con los valores a publicar: no intentes dejar Enabled sin DNS. Cada subdominio que envíe correo necesita su propia configuración DKIM según Microsoft.

  5. 5. Verifica con el verificador DKIM

    Usa el verificador DKIM de InboxSeguro con los selectores que Microsoft te indicó (no inventes el nombre).

  6. 6. Publica el TXT DMARC en _dmarc

    Hostname _dmarc, valor inicial: v=DMARC1; p=none; rua=mailto:dmarc@ejemplo.cl. Microsoft documenta p=none para prueba, p=quarantine (aceptar pero marcar; a menudo spam/junk) y p=reject (típicamente descartar / no entregar). También documenta pct para despliegue gradual, aunque RFC 9989 lo marcó histórico.

  7. 7. Monitorea y endurece la política

    Revisa reportes agregados (rua). Sube a quarantine y luego reject solo con fuentes legítimas alineadas. Verifica la política p= con el verificador DMARC.

Cómo verificar con herramientas del sitio

  • Verificador DKIM — confirma el selector publicado.
  • Verificador DMARC — verifica la política DMARC (p=) de tu dominio.
  • Chequeo de seguridad del correo — vista conjunta SPF/DKIM/DMARC.

Avance none → quarantine → reject

  1. p=none: observa reportes; no cambia la entrega por política DMARC.
  2. p=quarantine: los fallos pueden ir a spam/cuarentena del receptor. Google, Microsoft y Zoho aún documentan pct para aplicar la política a un porcentaje; el estándar actual (RFC 9989) eliminó pct y usa t=y/t=n.
  3. p=reject: los fallos no se entregan (rebote/descarte). No equivale a «enviar a spam».

InboxSeguro ofrece guía gradual DMARC, monitoreo de DNS (SPF/DKIM/DMARC/BIMI/MTA-STS/RUA) con alertas de cambios no autorizados, detección de suplantación y analítica semanal desde reportes DMARC.

Errores frecuentes

  • Intentar Enabled sin haber publicado los CNAME.
  • Mezclar formato CNAME antiguo y nuevo para el mismo selector.
  • Configurar solo el dominio raíz y olvidar subdominios que envían.
  • Interpretar p=reject como «va a spam».
  • Múltiples registros DMARC en el mismo nombre.
